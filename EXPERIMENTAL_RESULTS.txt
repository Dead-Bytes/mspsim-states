================================================================================
                                KEY FINDINGS
================================================================================

1. ACCURACY vs SAFETY TRADE-OFF VERIFIED:
   
   • High-accuracy models (XGBoost, RF): 7-8% MAPE but 43-44% underestimation
     → Predict LOWER energy consumption
     → System executes MORE blocks (2,222-2,355)
     → But triggers MORE checkpoints (86-90)
   
   • Safety-focused models (GB, QLR): 31-52% MAPE but <2% underestimation
     → Predict HIGHER energy consumption
     → System executes FEWER blocks (1,230-1,346)
     → But triggers FEWER checkpoints (52-54)

2. CHECKPOINT EFFICIENCY PARADOX:
   
   • Conservative prediction → FEWER checkpoints
     - Ensemble/GB: 52 checkpoints (2,600 nJ overhead)
   
   • Accurate prediction → MORE checkpoints  
     - XGBoost: 90 checkpoints (4,500 nJ overhead)
     - 73% MORE overhead than Ensemble!
   
   Explanation: Conservative models cause faster battery depletion, but
   the adaptive checkpoint strategy triggers checkpoints less frequently
   because the predicted high energy matches the aggressive depletion.

3. THROUGHPUT vs CHECKPOINT OVERHEAD:
   
   • XGBoost achieves 92% MORE blocks than Ensemble (2,355 vs 1,226)
   • But pays 73% MORE in checkpoint overhead (4,500 vs 2,600 nJ)
   • Net efficiency depends on application requirements

4. ENSEMBLE MODEL PERFORMANCE:
   
   • Successfully balances accuracy and safety
   • Tied for FEWEST checkpoints (52)
   • Reasonable throughput (1,226 blocks)
   • Validation of max(XGBoost*1.05, GB_Quantile) approach

================================================================================
                            RESEARCH QUESTIONS ANSWERED
================================================================================

RQ1: Can ML models accurately predict block-level energy in MSPSim?
     ✓ YES - XGBoost/RF achieve 7-8% MAPE, demonstrating high accuracy
     
RQ2: Does ML-driven checkpointing reduce checkpoint frequency?
     ✓ PARTIALLY - Conservative models (GB/QLR/Ensemble) reduce CPs by 42%
     ✗ BUT - Accurate models (XGB/RF) increase CPs vs baseline
     
RQ3: How does underestimation affect system reliability?
     ✓ CONFIRMED - High underestimation (43%) doesn't cause failures in
        adaptive strategy, but increases checkpoint frequency
     
RQ4: What is optimal accuracy-safety balance?
     ✓ ENSEMBLE MODEL - Combines XGB accuracy with GB safety
     → Achieves fewest checkpoints (52)
     → Maintains reasonable throughput (1,226 blocks)
     → Recommended for production use

================================================================================
                               RECOMMENDATIONS
================================================================================

FOR DIFFERENT USE CASES:

1. MAXIMUM THROUGHPUT (IoT sensors with stable power):
   → Use: XGBoost or Original
   → Pro: 2,355 blocks executed
   → Con: 90 checkpoints (4,500 nJ overhead)
   → Best when: Energy harvesting is reliable

2. CHECKPOINT EFFICIENCY (Battery-constrained systems):
   → Use: Ensemble or Gradient Boosting
   → Pro: Only 52 checkpoints (2,600 nJ overhead)
   → Con: 1,226-1,230 blocks executed
   → Best when: Minimizing checkpoint overhead is critical

3. SAFETY-CRITICAL (Medical devices, industrial control):
   → Use: Gradient Boosting with Quantile Loss
   → Pro: Only 1.79% underestimation
   → Pro: Only 52 checkpoints
   → Con: 31.68% MAPE (conservative predictions)
   → Best when: System failures are unacceptable

4. GENERAL PRODUCTION USE:
   → Use: Ensemble (max of XGBoost*1.05 and GB_Quantile)
   → Pro: Balanced approach
   → Pro: Fewest checkpoints (52)
   → Pro: Low underestimation (~2%)
   → Best when: Need reliability + efficiency
